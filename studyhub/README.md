# StudyHub

A personal, AI-powered study platform. It answers four questions the moment you
open it: **what do I have to do, what should I learn, what am I bad at, and
what exam is coming?**

The workflow it's built around:

```
Upload → Understand → Learn → Practice → Test → Track
```

Dark-first, keyboard-driven, and **fully usable the second you start it** — no
API key, no database, no signup.

---

## Run it

```bash
cd studyhub
npm install
npm run dev          # http://localhost:3000
```

That's the whole setup. On first load StudyHub seeds a realistic demo student
(Alex Rivera, 11th grade) with four subjects, six documents, notes, four
flashcard decks with real review history, graded quizzes, tasks, three exams
with study plans, and eight weeks of study sessions — so every chart, streak
and insight has something true to say.

Other commands:

```bash
npm run build        # production build
npm start            # serve the production build
npm run lint         # ESLint (currently clean)
```

## Environment variables

**None are required.** Copy `.env.example` to `.env.local` only if you want to
go beyond demo mode.

| Variable | Required | What it does |
|---|---|---|
| `ANTHROPIC_API_KEY` | no | Switches every AI feature from the built-in demo generator to a real model. Read **server-side only**, in the `/api/ai` route — never bundled into client code. |
| `ANTHROPIC_MODEL` | no | Model for AI calls. Defaults to `claude-sonnet-4-5`. |
| `NEXT_PUBLIC_SUPABASE_URL` | no | Reserved for the database/auth wiring described below. Not read yet. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | no | Same. |
| `SUPABASE_SERVICE_ROLE_KEY` | no | Same. Server-side only if you add it. |

Settings → **AI provider** shows live which mode you're in.

## What's in it

| Area | What it does |
|---|---|
| **Dashboard** | Due today, next exam, study time, streak, continue-learning, a 14-day timeline, and AI insights derived from your real data. |
| **Subjects** | Each subject gets a workspace with eight tabs — overview, documents, notes, flashcards, quizzes, tasks, exams, progress — plus weak topics and study stats. |
| **Documents** | Drag-and-drop upload (PDF/DOCX/image/text) with tags and processing status. Opening one gives a **split screen**: document left, AI right — summarize, explain simply, generate flashcards, generate a quiz, find key concepts, build a study plan, or just ask anything. |
| **Notes** | Tiptap rich-text editor: headings, lists, task lists, code blocks, links, images, and inline LaTeX via KaTeX. AI panel improves, summarizes, explains, finds gaps, or converts a note into cards/quizzes. |
| **Flashcards** | Decks by hand or generated by AI. Study mode has a 3D flip, `Space` to reveal and `1`/`2`/`3`/`4` to grade, scheduled by an SM-2-style algorithm (`src/lib/srs.ts`) tracking ease, interval, next review and confidence. |
| **Quizzes** | Generate from a topic, document or note — choose count, difficulty, question types (MCQ / true-false / short answer / fill-in-the-blank) and a time limit. Results break down mistakes, name your weak topics, and offer a one-click AI revision deck. |
| **Exams** | Enter subject, date, topics, level and hours available; StudyHub generates a week-by-week plan on a checkable timeline with a live readiness score. |
| **Tasks** | Drag-and-drop board across todo / in-progress / done, with priority, deadline, estimate, and recurring tasks that respawn on completion. Overdue is highlighted everywhere. |
| **Calendar** | Day / week / month views merging exams, deadlines and study sessions; click any event for details. |
| **Progress** | Study time, quiz trends, subject performance, flashcard retention, task completion and exam readiness — plus an on-demand AI weakness analysis per subject. |
| **AI Tutor** | Streaming chat with six modes (Explain, Socratic, Exam, Simplify, Practice, Review), subject and document context, markdown + math rendering, conversation history and suggested questions. |
| **Settings** | Profile, subjects, theme, live AI-provider status, JSON export, demo reset, full wipe. |
| **⌘K everywhere** | Raycast-style palette searching documents, notes, subjects, decks, tasks, exams, quizzes and conversations, with quick actions. |

**Keyboard:** `⌘K` / `⌘P` / `⌘F` palette · `⌘N` new note · `Space` flip card ·
`1–4` grade card · `Esc` close. Tab order and focus rings work throughout;
there's a skip-to-content link and the sidebar is fully collapsible.

│   │   ├── error.tsx       error boundary
│   │   └── loading.tsx     route skeleton
│   ├── api/ai/route.ts     the ONLY place AI credentials are touched
│   ├── layout.tsx  globals.css  not-found.tsx  icon.svg
├── components/
│   ├── ui/                 primitives (Radix + CVA): button, dialog, sheet,
│   │                       tabs, select, command, popover, tooltip, …
│   ├── layout/             sidebar, topbar, command palette, app shell
│   ├── shared/             empty states, stat cards, charts, markdown
│   ├── onboarding/  subjects/  documents/  notes/
│   └── flashcards/  quizzes/  exams/  tasks/  calendar/  ai-tutor/
├── lib/
│   ├── ai/                 ← AI layer, provider-agnostic (see below)
│   ├── store/              Zustand + persist: the data layer
│   ├── analytics.ts        every metric and insight, pure functions
│   ├── srs.ts              spaced repetition scheduler
│   ├── demo/seed.ts        the demo student

**Stack:** Next.js 16 (App Router, Turbopack) · React 19 · TypeScript (strict) ·
Tailwind CSS v4 · Radix UI primitives · Motion · Recharts · Tiptap · KaTeX ·
Zustand · cmdk · Sonner.

### The AI layer

AI is deliberately isolated from the UI. Nothing in `components/` or `app/`
imports a provider.

```
components  →  lib/ai/client.ts     (browser-safe fetch wrapper)
                     ↓  POST /api/ai
            →  lib/ai/service.ts    (decides live vs demo, always resolves)
                     ↓
      ┌──────────────┴──────────────┐
lib/ai/anthropic-provider.ts   lib/ai/demo-provider.ts
   (server-only, streaming)     (deterministic, content-aware)
```

`service.ts` exposes exactly the functions the product needs:
`generateSummary`, `explainTopic`, `generateFlashcards`, `generateQuiz`,
`createStudyPlan`, `analyzeWeaknesses`, `answerDocumentQuestion`,
`findConcepts`, `streamTutorReply`.

Three properties worth calling out:

1. **No hardcoded responses.** The demo provider doesn't return canned text —
   it parses *your* document or note (sentence splitting, definition-pattern
   extraction, distractor generation) and derives summaries, cards and quiz
   questions from that content. Upload a new PDF and paste its text: the
   flashcards are about that PDF.
2. **It never breaks.** If a live call fails or times out, the service silently
   falls back to the demo generator rather than surfacing a dead feature. Every
   AI result is tagged `live` or `demo` and the UI shows which you got.
3. **Keys stay server-side.** `ANTHROPIC_API_KEY` is read only inside
   `anthropic-provider.ts`, which is imported only by the API route.

Swapping providers means writing one file next to `anthropic-provider.ts` and
changing the branch in `service.ts`. Nothing else moves.

### The data layer

All state lives in one Zustand store (`src/lib/store/index.ts`) persisted to
`localStorage`, with `skipHydration` so SSR stays safe (a small
`StoreHydrator` triggers rehydration client-side). Store actions are named and
shaped to line up with the SQL in `supabase/schema.sql`, so replacing the
persist middleware with Supabase queries is a swap inside one module rather
than a rewrite.

Analytics are pure functions over that state (`src/lib/analytics.ts`) — no
metric is stored, so nothing can go stale or disagree with itself.

## What remains to be connected for production

The app is complete as a single-user local product. To ship it publicly:

1. **Auth** — Supabase Auth (or similar). Today there's one implicit local
   user; `profiles.id` already keys off `auth.users`.
2. **Database** — apply `supabase/schema.sql` (tables + RLS are written),
   then replace the `persist` middleware in `src/lib/store/index.ts` with
   Supabase queries. The action signatures don't need to change.
3. **File storage + real text extraction** — uploads currently keep metadata
   and whatever text you paste; the file bytes aren't stored. Wire Supabase
   Storage plus server-side extraction (`pdf-parse` / `mammoth` / OCR for
   images) and set `documents.storage_path`.
4. **AI key + real usage metering** — set `ANTHROPIC_API_KEY`. The AI-usage
   counter is currently incremented client-side per action; move it server-side
   and meter real tokens.
5. **Rate limiting** on `/api/ai`, since it proxies a paid API.
6. **Streak/session integrity** — study sessions are logged client-side and
   are therefore trivially forgeable; move logging behind the API if that
   matters to you.

## Notes

Demo data is fictional. The AI-usage meter is illustrative. Without an API key
every AI answer comes from the local demo generator — useful and grounded in
your own material, but not a real model, and the UI labels it as such.
